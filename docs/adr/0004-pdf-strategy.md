# ADR 0004：PDF 导出策略

- 状态：已采纳
- 日期：2026-10-18

## 背景

三个模块需要统一 PDF 导出：Word 分页、Excel 打印区域/分页、PPT 逐页导出，且要求进度、取消、
异常报告与页码/范围配置；同时避免“屏幕正确、打印错位”。

## 决策

V1 采用**前端 DOM 渲染 + html2canvas + jsPDF** 的统一导出服务（`packages/export-service`）：

- Word：按分页后的纸张 DOM 逐页截图，使用页面实际像素尺寸建立 jsPDF 页面。
- Excel：把数据区域构建为 A4 横向分页表格 DOM（重复表头、字体/填充/对齐/边框），逐页导出；
  打印复用同一套 DOM 与打印样式。
- PPT：屏幕外以原始尺寸渲染所有幻灯片，逐页导出；图片 ZIP 使用同一捕获结果。
- 支持页码范围（`1-3,5`）、进度回调、取消与失败提示。
- 等待 `document.fonts.ready` 后再捕获，减少中文字体闪烁。
- 临时 DOM 放在视口外但保持布局，导出完成后移除。

Rust `office-pdf` 提供 LibreOffice Headless 发现与转换，仅作为 PoC 对照后端：
`export_pdf` 命令在可用时调用，不参与常规前端导出。

## 理由

- 与预览使用同一 DOM，屏幕/打印一致性优于另起一套 PDF 排版器。
- 不增加 LibreOffice 安装包体积与启动成本；离线可用。
- 中文字体由 WebView 渲染，避免服务端缺字体。
- 前端导出可与编辑器状态、页码范围、取消逻辑自然结合。

## 后果

### 正面

- 三模块统一 API，行为一致；实现简单，便于快速验证。
- 图片/表格/形状/主题色按屏幕效果输出。
- 不需要分发外部二进制。

### 负面

- PDF 内是位图，文本不可搜索/选中；文件体积随页数与缩放增大。
- 高 DPI 下内存占用高，超长文档需分页/降采样。
- html2canvas 对部分 CSS（渐变、滤镜、复杂字体特性）支持有限。
- 打印依赖浏览器/WebView 的页面尺寸与缩放；不同平台可能分页不同。

## 测试

- Word/Excel/PPT 实际生成 PDF，检查 `%PDF` 头、页数对象、文件大小。
- PPT 图片 ZIP 解压后检查 3 张 JPEG。
- 真实 DOCX/XLSX/PPTX 样例。
- 后续应增加 PDF 版面像素对比（不同平台、不同字体）。

## 后续

1. 用矢量文本 + 图形直接生成 PDF（如 pdf-lib / print-to-PDF）替代整页位图。
2. 引入页面级缓存与按需渲染，降低大文档内存。
3. 将 LibreOffice 作为可选“高保真对照/转换”插件，不在默认安装包内。
