# ADR 0002：安全保存策略

- 状态：已采纳
- 日期：2026-10-18

## 背景

Office 文件是 ZIP 容器，包含主文档、样式、关系、媒体、批注、修订、宏、签名、嵌入对象等大量部件。
轻量编辑器若只导出自身模型，容易静默删除不支持的内容，造成合同版面或法律要素丢失。

## 决策

采用“**保留未知部件 + 仅重写已知部件 + 分级保存 + 原子提交**”策略。

### 1. 打开阶段

1. 校验 ZIP 魔数、旧版 OLE、条目数量、解压大小与压缩比（`office-security`）。
2. 解包并解析主文档、关系、样式、媒体；同时扫描宏、签名、修订、批注、内容控件、嵌入对象、
   动画、外部链接、图表、透视表等能力。
3. 生成 L0–L3 报告：
   - 宏/签名/旧格式 → L1 只读；
   - 修订/批注/内容控件/嵌入对象/图表/透视表/外部链接等 → L2 可编辑但必须另存副本；
   - 干净文档 → L3。
4. 缺失字体只产生渲染警告，不降低保存等级（字体名会原样写回）。

### 2. 编辑阶段

- 内部模型只覆盖已验证的能力。
- 不支持的对象不在 UI 中伪造编辑入口；兼容性对话框明确说明。
- DOCX 保留原始页眉/页脚、编号、样式、媒体与其他部件。
- XLSX 保留主题、媒体、图表、透视表等原始部件（即使 V1 不渲染）。

### 3. 保存阶段

```text
serialize（保留未知部件）
  → 平台适配器
  → 临时文件写入
  → fsync
  → 校验 OOXML 容器（Tauri write_file）
  → 备份原文件（时间戳 + 随机后缀）
  → 原子 rename 替换
  → 更新快照/最近文件
```

- DOCX：复制源 ZIP 的全部条目，仅替换 `word/document.xml`；新增图片补关系与内容类型。
- XLSX：重建 `workbook.xml`、`styles.xml`、工作表 XML，删除 `calcChain.xml` 并强制重算；
  其余部件原样保留。
- PPTX：V1 只读，保存直接返回源字节（不会写回）。
- L2 文档首次保存强制 `Save As`；之后可继续保存副本。
- 保存失败进入 `SAVE_FAILED`，保留未保存状态和恢复快照；临时文件与备份保留用于排查。

### 4. 自动恢复

- 编辑后防抖序列化完整文件，写入 IndexedDB（Web/Tauri WebView），最多 12 个 / 160 MB。
- 恢复后的会话标记为未保存、无原始路径，保存时必须另存。
- 应用重启后首页显示未保存快照并提供恢复。

## 后果

### 正面

- 不会因为“不认识”而删除整个部件；宏/签名等敏感内容默认不覆盖。
- 保存失败可恢复；原文件有备份。
- 兼容性等级直接映射到交互，用户可理解风险。

### 负面

- DOCX 重新生成主文档会丢失超链接/修订锚点等主文档级未支持结构（已用 L2 警示）。
- XLSX 重建工作表会丢失图表/绘图引用；图表部件虽保留，但显示可能需要重新挂接。
- 对 ZIP 做“原子替换”只能保证文件系统级原子性；跨平台行为不同（Windows 回退为先删后改名，
  已保留备份）。
- 自动恢复写入完整文件，大文件会有 I/O 压力（受防抖与 160 MB 上限约束）。

## 测试

- Rust：路径穿越、压缩炸弹、宏/签名检测、原子写入 + 备份、恢复快照。
- TS：真实 DOCX 保存后页眉/图片/表格保留；XLSX 二次往返；CSV BOM。
- 手工：保存后用 Microsoft Word / LibreOffice / openpyxl / python-docx 重新打开。

## 后续

- 以“部件级差异”测试替代仅重新打开测试。
- 支持保留主文档中未知 XML 片段（超链接、书签、复杂域）。
- Windows 使用 `ReplaceFileW` 实现真正原子替换。
- 自动恢复改为增量/压缩快照。
