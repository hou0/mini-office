# Word 邮件合并功能分析

日期：2026-10-24；作者：lq。本文记录实现前的功能分析与建议；当前已实现的范围、操作方式与验收限制见 [邮件合并使用说明](word-mail-merge.md)。

## 它解决什么问题

邮件合并把固定格式的 Word 模板与多条数据组合，为每条记录生成一份文档。常见用途包括通知、证明、证书、工资条、合同和报告。名称里有“邮件”，但也可只生成或打印文档。

截图中“设置模板、导入 Excel、按条件选择、批量打印报告”的需求，属于典型的文档合并。这里把截图当成使用场景，没有把截图中的对话当作执行指令。

例如模板为：

> 检测报告：«报告编号»
>
> 委托单位：«单位名称»
>
> 样品：«样品名称»；检测结果：«结果»；日期：«报告日期»

Excel 第一行列名为“报告编号、单位名称、样品名称、结果、报告日期”；后面每行是一份报告的数据。100 行就可以生成 100 份同版式、不同内容的报告。Word 中的真实合并字段是 MERGEFIELD 域，尖括号这里只作阅读示意。

## 在 Microsoft Word 中如何使用

1. 先完成 Word 模板的文字、表格、页眉页脚和页面布局。
2. Excel 准备一行表头，每列一个字段、每行一条记录；不要用合并单元格充当数据区域。
3. Word 的“邮件”选项卡中，开始邮件合并，选择“信函”等文档类型。
4. 选择收件人 → 使用现有列表，选择 Excel 文件与工作表。
5. 光标放到模板需要变化的位置，通过“插入合并域”选择对应列名。
6. 编辑收件人列表，筛选、排序并勾选要输出的记录。
7. 预览结果，前后翻记录，检查空值、日期、金额和分页。
8. 完成并合并，生成可编辑文档或打印选中的记录。

来源：[Microsoft：使用 Excel 电子表格进行邮件合并](https://support.microsoft.com/en-us/word/mail-merge-using-an-excel-spreadsheet)。

## 报告场景的边界

- 一条记录对应一份报告：很适合，尤其是固定表格、固定栏目。
- 一份报告有数量不定的检测项目：需要一对多数据与可重复表格行，不能只做简单字符串替换。
- 日期、金额、百分比、编号前导零：必须让用户明确输出格式；手机号、证件号及带前导零编号应按文本处理，避免精度丢失。
- 空值或缺少列：生成前列出错误所在行与字段，允许用户选择修正或跳过，不能悄悄生成不完整报告。
- 每份报告多页：应明确“每份重新从 1 编号”或“整批连续编号”；每份总页数也应独立计算。
- 自动发送电子邮件：还涉及邮件账户、收件地址、发送失败与权限，不是批量打印报告的必要条件。

数据格式注意事项来源：[Microsoft：准备邮件合并的 Excel 数据源](https://support.microsoft.com/en-us/word/prepare-your-excel-data-source-for-a-word-mail-merge)。一对多支持及交互设计为本项目的实现分析。

## Mini Office 当前基础与缺口

已检查 `packages/document-model/src/word.ts`、`packages/editor-word/src/parse.ts`、`serialize.ts`、`WordEditor.tsx` 及 `packages/editor-sheet/src/format.ts`。

项目已有 Word 段落、富文本、表格、图片、分页、DOCX 保存和 PDF 导出，也有 Excel 数据模型、读取与显示格式。这些能力可以复用。

当前没有找到邮件合并操作入口、MERGEFIELD 专门模型、字段绑定、记录筛选、合并预览或批量生成流程。现有 PAGE / NUMPAGES 页码域不等于邮件合并支持，不能据此宣称兼容 Word 合并模板。

## 建议实现范围与交互

建议把入口命名为“邮件合并 / 批量生成”，用四步流程帮助没用过的人完成第一次操作：

1. **选择数据**：导入 XLSX/CSV 或选择已打开的工作簿，选择工作表和表头行；先展示数据预览、字段和记录数。
2. **制作模板**：点击字段插到光标位置，以可识别、不可误拆开的字段块显示；正文、表格单元格均可插入。保存模板时使用真正的 MERGEFIELD 域。
3. **选择记录并预览**：支持勾选、全选、条件筛选、排序；显示“选中 35 / 共 100 条”，逐条预览替换后的真实版式，生成前集中展示缺字段、空值等问题。
4. **批量生成**：先支持合并为一个 DOCX/PDF，以及按记录拆分文件并打包下载；文件名可用“报告编号_单位名称”。提供进度、取消和失败明细。

第一期建议聚焦“一行一份文档、正文/表格字段、勾选筛选、预览、批量 DOCX/PDF”。一对多表格、IF 条件段落、NEXT RECORD、标签信封、外部数据库连接、自动发邮件可分后续阶段处理。

## 实现要点与验收

- 字段应在 DocRun 中作为结构化数据表达，解析与写回 MERGEFIELD；不能依赖替换整段 HTML 或 XML，以免破坏跨字体字段及样式。
- 从模板深拷贝生成结果，不能覆盖模板或修改源 Excel。优先采用数据快照，让本次预览与生成使用同一批数据。
- 优先复用 Excel 的格式化显示值，同时保留原始值用于数字筛选；CSV 需验证编码、分隔符、重复/空表头。
- 批量生成应分批处理、显示进度并允许取消，避免大批数据阻塞界面；上线前通过实测确定记录数和输出大小限制。
- 合并成一个 DOCX 时，处理每份文档的节、页码重启和总页数域；导出独立文件则先独立分页。现有单默认节模型不能直接保证多报告分节行为。
- 若生成 PDF，要逐份验证字段替换后自动分页；物理打印仍需要真实设备验收。
- 至少验收：中文长姓名、空值、跨字体字段、表格字段、前导零、长编号、日期金额、长文本跨页、筛选后记录数、重名文件、取消，以及保存到 Word 后重新打开。

建议做这个功能：对截图中的用户价值明确，且 Word 与 Excel 已有基础能力可以复用。主要工作集中在结构化字段、数据选择和批量输出的完整链路；本次先交付页眉页脚，邮件合并保持为分析与设计。
